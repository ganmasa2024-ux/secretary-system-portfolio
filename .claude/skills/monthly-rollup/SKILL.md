# monthly-rollup

月ごとに、日々の振り返りを短い1ファイルにまとめる。元のファイルは消さず、フォルダに移して残す。

## いつ使うか

- 「先月分のまとめを作って」「月次まとめして」と言われたとき(月は指定がなければ前の月)。
- 月が変わった最初の会話で、前の月のまとめがまだ無いとき。この場合は**勝手に実行しない**。まず次のように聞く。
  - 「先月(〇月)分のまとめを作りましょうか?」
  - 「はい」など了承の返事があってから実行する。「あとで」「いいえ」なら実行せず、その会話では再度聞かない。

## まとめが必要かの判定(提案するとき)

次の2つがどちらも当てはまるときだけ提案する。

1. `reviews/` の直下に、前の月の日々のファイル(`YYYY-MM-*.md`、例: `2026-10-*.md`)が1つ以上ある。
2. `reviews/archive/YYYY-MM-summary.md` がまだ無い。

どちらかが外れるときは、何も言わない。`reviews/` が無いときも何も言わない。

## 手順(了承を得てから)

1. 対象の月(`YYYY-MM`)を決める。
2. `reviews/YYYY-MM-*.md` を日付順にすべて読む。`reviews/archive/` の中は読まない。
3. 要約を `reviews/archive/YYYY-MM-summary.md` に書く。
   - `reviews/archive/` が無ければ作る。
   - すでに同じ名前のファイルがあるときは、上書きせず、ユーザーに確認する。
4. 要約ファイルを書けたことを確かめてから、元の日々のファイルを `reviews/archive/YYYY-MM/` に移動する。
   - フォルダが無ければ作る。
   - 移すだけで、削除はしない。移動先に同名のファイルがあるときは、上書きせず、ユーザーに確認する。
   - 要約が書けていないときは、移動しない。
5. 何を作り、どこへ移したかを日本語で短く伝える(例: 「要約を作成し、振り返り8件を archive/2026-10/ に移しました」)。

## 要約の書き方

```
# 2026年10月のまとめ
対象: 8日分(10/22〜10/31)

- タスク: (追加・完了したことを1〜2行)
- 家計: (登録・記録したことを1〜2行)
- 設定・スキル: (作った・直したことを1〜2行)
- ユーザーが言った好み・判断: (言われた言葉をそのまま、重複はまとめる)
```

- 全体で15行以内を目安にする。日付ごとの再掲はしない。
- 日々のファイルに書いてあることだけをまとめる。推測や評価は足さない。
- 該当が無い項目は書かない。
- 金額などの実データは、必要最小限にする。

## 守ること

- 操作の前に、何をするかを専門用語なしの日本語で説明する。
- 了承なしに、要約の作成やファイルの移動をしない。
- 元の振り返りファイルを削除しない。
- `reviews/` には実データが入るので、ポートフォリオなど人に見せる場には出さない(CLAUDE.mdのルール)。
