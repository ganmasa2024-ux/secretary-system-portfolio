# session-review

その会話で行ったことを、今日の日付のファイルに短く書き足す。SessionEnd(終了イベント)は使わない。画面を閉じるだけでは動かないため、締めの言葉をきっかけにする。

## いつ使うか

- 「振り返りして」と言われたとき
- 会話を締めくくる言葉が出たとき(例: 「今日はここまでです」「お疲れ様でした」「今日は終わります」「また明日」)。頼まれていなくても実行する。
- 同じ会話で2回目の締めの言葉が出たときは、前回の追記から増えた分だけを足す。変わりがなければ「追記する内容はありません」と伝える。

## 手順

1. 今日の日付(`YYYY-MM-DD`)を確認する。
2. この会話で実際に起きたことだけを集める。
   - タスク: 追加・更新・完了したもの(`data/tasks.json`)
   - 家計: 追加した収入・支出・固定費(`data/finance.json`)
   - 設定・スキル: 作った、または直したスキルやルール
   - ユーザーが実際に言った好みや判断基準(言葉として出たものだけ)
3. `reviews/YYYY-MM-DD.md` に追記する。
   - `reviews/` が無ければ作る。
   - ファイルが既にあれば、末尾に足す(上書きしない、既存の内容を消さない)。
   - 無ければ、1行目を `# YYYY-MM-DD` にして作る。
4. 追記したら、何を書いたかを日本語で短く伝える。

## 書き方

```
## 17:40 振り返り
- タスク: 〇〇を追加、△△を完了
- 家計: 固定費10件を登録(合計〇〇円)
- 設定: money-summaryを月末払いに対応
- 好み・判断: 「〇〇」と言われた(言葉のとおり)
```

- 該当が無い項目は書かない。全体で10行以内を目安にする。
- 日記にしない。出来事と、実際に言われたことだけを書く。
- 推測を書かない。「〜と思っているはず」「〜が好きなようだ」は禁止。好み・判断は、ユーザーが言った言葉をそのまま、または近い言い方で書く。言われていなければ、その項目は書かない。
- 金額など実データは、必要最小限にする。

## 守ること

- 操作の前に、何をするかを専門用語なしの日本語で説明する。
- `reviews/` には実データが入るので、ポートフォリオなど人に見せる場には出さない(CLAUDE.mdのルール)。
- 振り返りの追記以外のファイル(`data/` など)は変更しない。
